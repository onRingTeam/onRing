## 4. 회의 종료 브로드캐스트 (`1e8e06a`)

**문제**: 개설자가 회의를 종료해도 참여자는 회의 화면에 그대로 남음.

**설계**: STOMP 네 번째 토픽 신설 — `/topic/meetings/{id}/status`

```
개설자 종료 (POST /api/meetings/{id}/end, 200)
  → 서버: MeetingStatusEvent(type=ENDED) 를 status 토픽으로 발행
  → 참여자: 수신 → 스토어 정리 → 요약 화면(/notes/{id}?fresh=1) 이동
```

- **백엔드**: `MeetingStatusEvent` DTO(`MessageDto.kt`), 종료 API 성공 시
  `SimpMessagingTemplate.convertAndSend` 발행 (`MeetingController`).
- **프론트**: `MeetingSocket` 에 status 토픽 구독 + `onStatus` 콜백 추가(`websocket.ts`),
  `useMeetingConnection` 에 `onMeetingEnded` 파라미터 추가(`meeting-room/hooks.ts`).
  타입 계약은 `types/meeting.ts` `MeetingStatusEvent` (백엔드와 1:1).

## 5. 회의화면 개선 (`926b63d`)

- **자막 자동 스크롤**: 새 메시지로 내용 높이가 변하면 `scrollToEnd` — 최신 메시지 항상 노출.
- **종료 버튼 개설자 전용**: `activeMeeting.host`(생성/참여/홈 동기화 응답의 host 플래그)가

- **종료 알림 수신 처리**: 위 4번 브로드캐스트를 받아 `finishLocally()` 실행.
  내가 누른 종료와 STOMP 알림이 겹쳐도 `endedRef` 가드로 1회만 처리.

## 참고: AI 요약 중복 생성 검토 결과 (코드 변경 없음)

양쪽에서 종료를 눌러도 요약은 중복 생성되지 않음을 확인:

1. `MeetingService.end()` — 개설자 아니면 403, 이미 종료면 409.
2. 컨트롤러에서 `end()` 가 던지면 요약 트리거(`clearChat`)까지 도달하지 않음.
3. `MeetingChatBuffer.clear()` 의 `buffers.remove()` 가 원자적이라
   어떤 경로로든 `MeetingChatArchivedEvent` 는 최대 1회 발행.

## 로컬 개발 환경 메모

- `app/knou-app/.env.local` 에 `EXPO_PUBLIC_API_BASE=http://localhost:8080` /
  `EXPO_PUBLIC_WS_URL=ws://localhost:8080/ws` 오버라이드 추가 (git 미추적).
  기본값 `10.0.2.2` 는 에뮬레이터 전용이라 실기기에서 백엔드 연결 실패 →
  `adb reverse` 와 조합하면 에뮬레이터·실기기 모두 동작.
- 기기 연결 시 필요한 포트 포워딩:
  `adb -s <기기> reverse tcp:8081 tcp:8081 && adb -s <기기> reverse tcp:8080 tcp:8080`
- 실기기는 Expo Go 불가(WebRTC 등 네이티브 모듈) — dev client 빌드 설치 필요:
  `npx expo run:android --device <기기명>`
